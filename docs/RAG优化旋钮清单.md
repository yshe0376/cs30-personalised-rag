# RAG 优化旋钮全清单

按流水线阶段罗列所有可调的地方。★ = 对课程项目性价比高（改动小、提升明显、答辩讲得清楚）。

每次只改一个旋钮，记录 Recall@k 和正确率的变化——这样每一行都能变成消融表里的一行。

## 你已知的三个，其实是十五个

### chunk size → 切分策略（4 个旋钮）

| 旋钮 | 可选值 | 说明 |
|---|---|---|
| 块大小 | 100 / 200 / 500 / 1000 字 | 小块检索准、上下文残缺；大块反之 |
| 重叠比例 | 0 / 10% / 20% | 防止关键句落在切口上 |
| ★ 切分边界 | 定长 / 句子 / 段落 / 标题层级 / 语义突变点 | 定长最差，标题层级对 PDF 最好 |
| ★ 检索单元 ≠ 生成单元 | 父子块、句子窗口 | 用小块检索，喂大块给模型，一次解决"准"和"全"的矛盾 |

**语义切分（semantic chunking）**：逐句算相邻句的向量相似度，在相似度骤降处下刀——那里通常是话题转折点。比定长优雅，但慢，且对短文档收益有限。

### top-k → 上下文选择（6 个旋钮）

| 旋钮 | 可选值 | 说明 |
|---|---|---|
| k | 3 / 5 / 10 | 不是越大越好，噪声会稀释注意力 |
| ★ 两阶段 | 粗召回 20 → 精排 3 | 召回要广、精排要准，性价比最高的结构改动 |
| 相似度阈值 | 绝对值 / 相对最高分的比例 | 全都低于阈值就拒答 |
| ★ 多样性 MMR | λ = 0.5~0.8 | 选片段时惩罚"和已选内容太像的"，解决相邻块冗余 |
| 预算方式 | 固定条数 / 固定 token 总量 | 按 token 截断更合理，块有长有短 |
| ★ 片段顺序 | 相似度序 / 原文序 / 最相关放两端 | 模型对中间内容注意力最弱（lost in the middle） |

### embedding model → 向量方案（5 个旋钮）

| 旋钮 | 可选值 | 说明 |
|---|---|---|
| ★ 模型 | bge-small/base/large-zh、bge-m3、gte、jina、text-embedding-3 | 中文优先 bge 系列 |
| 向量维度 | 384 / 768 / 1024，部分模型支持降维 | 维度换速度和存储 |
| ★ 查询指令前缀 | bge 系列查询侧需加固定前缀 | **不加会明显掉点，很多人踩这个坑** |
| 非对称编码 | 查询和文档用不同前缀/不同模型 | 问题短、文档长，本就该区别对待 |
| ★ 微调 | 用自己的 QA 对做对比学习 | 领域数据上提升最大，也是最强的答辩亮点 |

## 以下是通常被忽略、但收益很高的部分

## A. 索引前：文档处理层

这层最被低估。**解析错了，后面全是错的，任何算法都救不回来。**

- ★ **解析质量**：双栏顺序、表格结构、公式、扫描件 OCR
- ★ **清洗**：去页眉页脚（每页重复的行）、去水印、去重复段落
- ★ **元数据抽取**：标题层级、页码、章节、文档名、日期 → 存进 chunk，既能做过滤又能做引用溯源
- ★ **上下文增强（Contextual Retrieval）**：每个 chunk 做 embedding 前，先拼上一句"本段出自第 3 章《实验设置》，讲的是数据集划分"。让孤立的块带上它的上下文身份，对"片段从半句话开始"这类问题效果显著
- **假设问题索引（doc2query）**：给每个 chunk 用 LLM 生成 3 个"这段能回答什么问题"，把问题也存进索引。用户问题和假设问题匹配，比和陈述句匹配更自然
- **摘要索引**：为长文档/章节生成摘要单独建索引，做粗粒度定位
- **表格与公式单独成块**，转 Markdown 表格存，别混进正文

## B. 查询处理层

用户的问题几乎从来不是检索的最佳形式。这层几乎不用改架构，只加一次 LLM 调用。

- ★ **查询改写**：口语 → 书面，补全省略成分
- ★ **多查询（Multi-Query）**：让 LLM 把问题换 3 种说法分别检索，结果合并。对付"用户措辞和文档措辞对不上"
- **HyDE**：先让 LLM 凭空编一个假答案，用**假答案**去检索。因为答案和文档的措辞更接近，而问题和文档的措辞差得远
- **查询分解**：复杂问题拆成子问题分别检索（"A 和 B 相比如何" → 查 A、查 B）
- **查询路由**：判断该查哪个索引、或压根不需要检索（闲聊、打招呼）
- ★ **多轮指代消解**：把"它的准确率是多少"里的"它"还原成上一轮的实体。**做对话就必须有这个**，否则第二轮开始全崩

## C. 检索层

- ★ **混合检索**：BM25 + 向量，用 RRF 融合（`score = Σ 1/(60+rank)`）。向量抓语义，BM25 抓专有名词、型号、公式编号
- **稀疏向量 SPLADE**：介于 BM25 和稠密向量之间，兼顾字面与语义
- ★ **元数据过滤**：先按章节/时间/文档类型筛掉一批再算相似度，又快又准
- **多路召回**：向量 + 关键词 + 标题匹配 + 元数据，各召一批再融合
- **图检索 GraphRAG**：抽实体关系建图，适合回答"跨多个文档的关联型问题"，成本高
- **索引参数**：数据量大时 HNSW 的 `M`、`ef_search` 会影响召回率与速度的平衡

## D. 重排层

- ★ **Cross-encoder 重排**：`bge-reranker-base`，把问题和候选块拼在一起送进模型算相关性。比 embedding 精确得多，只能用在小候选集上——所以必须配合两阶段检索
- **LLM 做重排**：直接让大模型给候选块打分，效果好但慢且贵
- **规则加权**：标题命中加分、文档较新加分、来源权威加分
- ★ **去冗余**：内容重叠度过高的块合并或丢弃

## E. 上下文组装层

检索完到发给模型之间，这段常常什么都不做，其实有得做。

- ★ **相邻片段合并**：命中 #3 和 #4 就拼成一块，比分开放更连贯
- ★ **补全上下文**：命中小块后，把它前后各扩一块一起给（sentence-window）
- **上下文压缩**：用小模型把每个块里和问题无关的句子删掉，省 token 也降噪
- ★ **带上元数据**：把页码、章节标题一起放进 prompt，模型就能生成"见第 12 页"这类可核对的引用
- **重排顺序**：把最相关的放开头和结尾

## F. 生成层

- ★ **约束句**：只根据资料回答，没有就说不知道
- ★ **要求标注引用**：让模型输出 `[片段2]`，答案可溯源
- **先引用后回答**：要求模型先摘录依据原文，再基于摘录作答。能明显降低编造
- **输出格式约束**：JSON / 固定结构，便于后处理
- ★ **拒答机制**：相似度全都很低时直接拒答，而不是硬答
- **模型与温度**：问答场景温度调低（0~0.3）
- ★ **引用校验（后处理）**：检查模型标的片段编号是否真实存在、被引原文是否真含该内容。**编造引用是最隐蔽的幻觉**

## G. 评估层

不是优化项，是所有优化的前提。

- ★ **检索侧**：Recall@k、MRR、命中位置分布
- ★ **生成侧**：正确率、忠实度（有没有编）、拒答准确率
- ★ **失败归因**：答错的例子逐条分类——没召回 / 召回了没用 / 切分切断了 / 模型编了
- **成本与延迟**：每个模块加了多少毫秒、多少 token
- **人工抽检**：自动指标测不出"答得好不好读"

## 本项目当前实际接上线的旋钮（W4）

上面是通用清单。这一节只记**本仓库里已经实现、且能从配置改到的**旋钮——做实验时照这张表拧，别照上面那张。

配置优先级：`src/cs30/configs/<env>.toml` < 环境变量 < CLI 参数。

| 配置字段 | 环境变量 | 默认 | 对应上文 | 状态 |
|---|---|---|---|---|
| `retrieval.mode` | `CS30_RETRIEVAL_MODE` | `hybrid` | C 层 ★ 混合检索 | 可用。`bm25` / `dense` / `hybrid` 三档，也是消融的主轴 |
| `retrieval.top_k` | `CS30_TOP_K` | 3（dev）/ 5（staging） | top-k ★ | 可用 |
| `retrieval.rrf_k` | `CS30_RRF_K` | 60 | C 层 RRF 的 `k` | 可用。60 是文献惯例值，本语料上未验证 |
| `retrieval.rrf_input_top_k` | `CS30_RRF_INPUT_TOP_K` | 20 | ★ 两阶段的"粗召回"宽度 | 可用。融合前每一路取多少候选 |
| `retrieval.bm25_min_score` | `CS30_BM25_MIN_SCORE` | `0.0` | F 层 ★ 拒答机制 | 可用但**未校准** |
| `retrieval.dense_min_similarity` | `CS30_DENSE_MIN_SIMILARITY` | `None`（关闭） | F 层 ★ 拒答机制 | 可用但**未校准**，见下 |
| `retrieval.index_dir` | `CS30_INDEX_DIR` | `data/index` | — | 不是旋钮，是 M5 产物的位置 |

### 尚未暴露到配置的旋钮

改这些要动构造参数，暂时只能在代码里调：

- **BM25 停用词表**（`retrieval/real.py` 的 `_STOPWORDS`）。这是个**真旋钮**，不是实现细节：换一份表就是一次消融。目前是硬编码的 33 个英文功能词，只作用于查询侧，索引侧的词频和 IDF 不受影响。
- **BM25 的 `k1` / `b`**（默认 1.5 / 0.75，Okapi 惯例值）。
- **查询指令前缀**（`FaissDenseRetriever.query_instruction`）。上文标了 ★ 并注明"不加会明显掉点"——目前从 `IndexArtifact.metadata.query_instruction` 读，M5 建索引时没写这个字段，所以现在等于没加。**换 bge 系列模型时必须先把这条接上。**

### 两个拒答阈值为什么默认是关的

`docs/backlog.md` 把 "calibrated abstention thresholds" 列在 out of scope 里，理由不变：**阈值要靠评估集校准，先拍一个数字等于给消融表注入一个没人能解释的常数。**

现状是不对称的，做实验前必须知道：

- **BM25 路能拒答**，但靠的不是阈值，是查询侧去停用词之后"一个实词都没命中"。`bm25_min_score=0.0` 表达的就是这个语义。
- **Dense 路完全不能拒答**。FAISS `IndexFlatIP` 无条件返回 top_k，`dense_min_similarity=None` 时没有任何下限。
- **因此 `mode=hybrid`（默认档）目前也不能拒答**——BM25 那一路返回空，dense 那一路照样吐满 k 条，融合完仍有结果。

所以 **W4 阶段谈拒答，只有 `mode=bm25` 是成立的**。dense 和 hybrid 的拒答要等 `dense_min_similarity` 校准（依赖 B4 评估集），校准本身就该是消融表的第一行。

### 拒答属性由 CI 守着，不靠约定

`ci.yml` 的 `smoke` job 对 `tests/fixtures/index/` 跑两条真实模式断言：离题问题必须拒答，在题问题必须作答且引用有据。**两条缺一不可**——只有前一条的话，一个"永远返回空"的检索器也能通过。改任何检索旋钮之后这两条都会跑。

## 怎么跑一次阈值校准

来自 M6 的检索消融方案（`docs/retrieval-ablation-plan.md`，随 #101 落地）。写在这里是因为它不只适用于 `dense_min_similarity`——任何"要定一个数"的旋钮都该走这套。

1. 把标注问题分成 **validation** 和 **test** 两份
2. 两份都要同时包含**可答**和**不可答**的问题——只有可答问题，拒答行为根本测不出来
3. 先把阈值关掉（`dense_min_similarity=None`）跑一遍完整检索
4. 记录三类 query 的相似度分布：命中了相关证据的、命中了无关证据的、本就不可答的
5. **只在 validation 上**扫候选阈值
6. 可答问题用 Hit@K / Recall@K / MRR 衡量检索质量
7. 不可答问题用拒答的 precision / recall / F1 衡量拒答行为
8. 选一个"明显改善拒答、又没把可答问题的 recall 拉垮"的值——这是个权衡，不是找最优点
9. **跑 test 之前先冻结**这个值
10. 报告里同时给出**未过滤基线**和校准后结果

底线一句话：**test 集不参与选阈值。** 用 test 挑出来的数字，报出去就是自欺。

## 每一行消融必须记录什么

`CLAUDE.md` 写了"实验结果统一记进消融表"，这是那句话的可执行版本。每行必记：

| | 字段 |
|---|---|
| 配置身份 | 检索模式、语料版本、评估集版本、embedding 模型 |
| 旋钮取值 | `top_k`、`dense_min_similarity`、`bm25_min_score`、`rrf_k`、`rrf_input_top_k` |
| 检索指标 | Hit@K、Recall@K、MRR |
| 拒答指标 | 拒答 precision / recall / F1（评估集含不可答问题时必填） |

**规矩：没有在同一评估集上跟对应基线比过，任何一个参数都不能被称作"提升"。** 报告里最容易被挑的就是这一点——写了"加了 X 提升 5%"却说不清和什么比。

前四个字段看着啰嗦，但少任何一个，这一行事后就复现不了：换了语料版本的两行放在一起比，结论是假的。

## 建议的动手顺序（课程项目）

```
0. 评估集 30~50 条  ← 没有这个，后面全是玄学
1. 跑基线，记数字
2. 解析 + 清洗 + 元数据（收益最大，也最枯燥）
3. 换 bge 向量（★ 记得加查询前缀）
4. 两阶段 + rerank
5. 混合检索 BM25 + RRF
6. 父子块 / 上下文增强
7. 引用标注 + 拒答
8. 失败归因分析
```

每步之间只改一个变量，测一次，记一行。八步做完就是一张完整的消融表。
