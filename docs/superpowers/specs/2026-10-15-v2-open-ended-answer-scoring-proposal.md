# V2 开放题答案评分方案草案

状态：离线正确性评分器已实现；量表提案仍待团队确认和实际人工校准，未作为正式评估标准冻结。
日期：2026-10-15。

## 1. 目的与当前边界

V2 Gold 使用 `gold_answer_text` 保存开放题参考答案。现有
`cs30.evaluation.answer_metrics` 将这类题标记为 `open_ended`，不纳入
`answer_choice_accuracy_*` 的分母；这两个行为应保留。

新增离线评分器读取已保存的模型输出，判断其是否满足题目要求。它不修改模型答案，
不补写 A–D 字母，也不将 Gold 参考答案送入答案生成提示词。

本方案分为三项交付：评分标准、评分程序、校准与复核记录。只有程序通过测试，
不能证明评分标准有效；人工校准与冻结记录仍需实际完成。

## 2. 三个维度分别报告

| 维度 | 回答的问题 | 评分依据 |
|---|---|---|
| 答案正确性 | 是否正确回答题目，并覆盖题目要求的必要内容？ | 题目、人工确认的评分要点、参考答案、权威教材证据 |
| 证据支持 | 实际送入模型或被引用的内容是否支持回答中的陈述？ | 原始模型回答、实际发送的 EvidenceBundle、引用子集 |
| 水平适配 | 表达是否适合指定学生水平？ | 独立的水平适配量表、指定水平、匿名答案 |

先分别给分，不设置把三者加权混成一个总分的公式。三个水平使用相同的事实正确性标准，
水平适配单独评估。初学者的简短正确回答不会仅因简短而被扣事实分。

正确性评审不能只看本次检索结果，否则检索漏掉事实时，可能错误地把事实正确的回答判错。
证据支持评审则必须受限于实际发送或引用的证据，不能用后来找到的教材替模型补证据。

## 3. 正确性使用 0 / 1 / 2 分

| 分数 | 判定 |
|---|---|
| 2：完全正确 | 满足至少一套最小充分回答要点，没有实质性错误或自相矛盾 |
| 1：部分正确 | 有相关且正确的回答要点，但缺少必要条件、步骤或要求；或只有不改变核心结论的次要错误 |
| 0：错误或未作答 | 核心结论错误、存在核心矛盾、关键数值/符号/量纲错误，或没有回答问题 |

优先检查核心错误，再检查内容完整性。出现正确关键词不能抵消错误结论。
“没有出现在简短参考答案中”不等于“错误”；无法用已确认依据判定的新增事实应转人工复核。

必要内容由题目决定：问术语，不强制额外推导；明确要求解释、比较、推导或计算，
才将相应内容列为必要要点。附加解释若产生严重物理错误，仍影响正确性。

示例题：什么术语表示与速度方向相反、使速度大小降低的加速度？

| 模型答案 | 分数 | 理由 |
|---|---:|---|
| Deceleration. | 2 | 术语题的核心答案完整 |
| 减速；加速度与速度方向相反。 | 2 | 同义表达，且物理关系正确 |
| 加速度与速度方向相反，使速度大小降低。 | 1 | 描述正确，但缺少题目明确要求的术语 |
| Negative acceleration. | 0 | 负加速度不一定使速度大小降低 |
| Deceleration，因为加速度与速度方向相同。 | 0 | 正确术语后存在核心物理矛盾 |

这些例子是量表演示，不是对尚未取得的 V2 Gold 的真实标注。

## 4. 每题增加独立的评分要点文件

建议使用 `open_answer_rubrics.jsonl` 作为 sidecar，按 `question_id` 关联原始 Gold，
避免为了评分改写 M3 交付文件。每题至少记录：

- Gold 文件哈希、Gold 标注版本、题目 ID、量表版本和复核记录。
- 最小充分回答要点；允许多套等价路径，路径之间为 OR，路径内部为 AND。
- 可接受的术语或表达别名，以及该题明确要求的解释、条件或步骤。
- 关键错误示例和对应教材依据；错误示例不是穷尽清单。
- 数值题的单位、方向约定、有效数字和逐题容差；推导题的假设与等价结果。

建议由 M3 确认题目含义和参考事实，M7 实现评分流程，M8 汇总报告，Leader 协调冻结。
分工是本提案的建议，不代表已分派给其他成员。

要点可以先由模型提议，但须经人工核对。不能根据哪个实验条件的答案更容易得分来修改要点。
Test 的题目级评分要点可由与系统调参隔离的评审人员准备；不得把 Test 答案或评分反馈
用于挑选生成模型、提示词、lambda 或 judge。Test 输出揭晓后若发现 Gold 缺陷，
记录勘误并对所有条件统一重评，不能只修正一个条件的得分。

## 5. 自动评分流程

1. 读取冻结的实验清单、Gold、要点文件和原始运行记录，核对 ID、版本及哈希。
2. 分开处理生成失败、模型拒答和正常回答。开放题的 `final_choice=null` 合法，
   正确性从完整 `explanation` 判断，不要求新增生成字段。
3. 确定性程序做大小写/空白等保守规范化，以及有明确规则的数值、单位检查。
   不删除负号、否定词、单位或决定意义的标点，不通过命中关键词直接判整段正确。
4. 语义评审读取题目、参考答案、已确认要点、参考教材证据和模型完整回答；
   对每个要点输出“满足 / 未满足 / 矛盾 / 无法判定”，并标记核心错误。
5. 程序根据这些结构化判断计算 0/1/2 分；judge 不能任意改变汇总规则。
6. 输出不合格式、依据不足、规则与 judge 冲突、重复评审不一致等情况，
   标记 `needs_review` 或 `judge_error`，保留原始记录，交人工处理。

Exact Match 和 token F1 可以作为诊断指标，不能作为开放题的唯一正式正确性标准。
同义表达不能只因字面不同被判错；包含正确词语的错误回答也不能因此通过。

数值题只在逐题容差和量纲规则明确时自动接受结果。符号计算需要检查适用假设，
不能把形式变换当成无条件等价。无法可靠解析的结果进入复核，不直接当成模型错误。

## 6. judge 的输入与可靠性

事实正确性评审隐藏 condition、模型名称、lambda、学生等级和提供方信息；
采用单份答案评分，避免通过并排排列顺序影响评审。水平适配评审单独提供目标等级。
答案和证据属于待评材料，不是评审指令；材料中要求改分、忽略规则等文字均不得执行。

建议使用与被评生成模型独立的 judge，并固定模型版本、提示词、参数和 JSON schema。
不同模型并不自动保证可靠；若只能使用同一模型自评，先标记为探索性结果，
不能把它称作独立验证。温度为零也不保证绝对可复现，应缓存评分结果并保留输出哈希。

建议先用 Dev 完成两轮工作：

- 校准集：约 60 份答案，按题型、四条件和三等级分层，两人独立评分后仲裁，修订量表。
- 独立验证集：再约 60 份答案，与校准集按题目隔离，检验冻结后的 judge，不能再用于调 judge。

样本量是项目工作量建议，不是统计保证。报告原始一致率、0/1/2 的加权 Cohen κ、
“完全正确”的混淆矩阵及其 precision/recall，并给出样本量和置信区间。
特别检查把核心错误判为完全正确的案例，以及对不同答案长度、条件和水平的偏差。
一致性不足时继续改量表或增加人工评分，不能仅因程序能跑就宣布评分有效。

正式人工盲评可复用团队现有抽样安排，并保留计划中的双人标注比例；
具体数量以最新冻结实验清单为准，不直接沿用旧文档中的固定总量。
自动分、人工分和仲裁分分别保留；自动全量统计与人工抽样统计分列展示。
非等概率抽样的人类评分估计需要使用抽样权重，不能简单当作总体准确率。

## 7. 主指标、分母与缺失记录

建议新增指标，不改旧的选择题指标含义：

| 指标 | 定义 |
|---|---|
| `open_answer_full_correct_rate_e2e` | 得 2 分的可回答题运行数 / 预定的、Gold 与量表有效的可回答题运行数 |
| `open_answer_mean_credit_e2e` | 同一分母下的平均 `score / 2`，仅作部分正确的补充指标 |
| `open_answer_full_correct_rate_answered` | 正常生成且已完成评分的回答中，得 2 分的比例；须同时展示覆盖率 |
| `scoring_coverage` | 已获得确定分数的预定运行数 / 预定有效运行数 |
| `technical_failure_rate` | 检索、生成、解析等技术失败的比例，独立报告 |

各指标标注评分来源，例如 `judge`、`human_sample`、`adjudicated`，不能把不同来源无说明地合并。
0.5 是部分分，不是“正确率里算半个答对”；严格正确率只统计得 2 分的答案。

对 `answerable=true` 的题：拒答和技术失败在端到端指标中记 0，
同时保留真实失败原因；不得把技术失败改写成“模型知识错误”。技术失败不进入
正常作答条件下的正确率分母，但必须报告数量。

judge 失败、待复核或未执行的预定运行属于未决记录，不等于模型答错，
也不能静默从端到端分母移除。设完整正确数为 C、未决数为 U、预定有效运行数为 N，
评分未齐时只展示正确率界限 `[C/N, (C+U)/N]` 和覆盖率，不发布一个假装完整的点估计。
每一项部分分也按对应的 `[已知分数和/(2N), (已知分数和+2U)/(2N)]` 展示界限。

`answerable=false` 使用单独的拒答评价；`answerable=null` 或 Gold/量表无效的题
不进入答案正确率分母，显式统计排除原因。全是可回答题时，不能据此声称验证了
不可回答题的识别能力。模型拒答与“judge 无法判定”必须是不同状态。

四条件使用相同的题目集合、等级、量表和评分版本。按等级分别报告；
总体指标只在等级覆盖完整且权重事先明确时汇总。比较条件差值时按题目做配对分析，
置信区间以题目为单位做 cluster bootstrap，保留同题下的各等级和条件，
不把这些重复结果当作独立样本扩大样本量。主要比较与多重比较处理需预先登记。

## 8. 证据支持与适配的配套规则

保留现有 citation ID 合法性与 Gold 证据覆盖指标。
引用存在于 EvidenceBundle，只说明引用合法，不说明该片段在语义上支持答案。

可增加两个明确区分的诊断指标：

- Bundle faithfulness：回答中可核查事实被实际发送证据支持的比例。
- Citation support：这些事实被答案实际引用的证据子集支持的比例。

逐条陈述记录支持证据 ID 和原文位置，并校验引文确实来自已保存证据。
主观措辞、重复事实和不可核查的修辞不增加事实计数。无可评事实时记 NA，不能记满分。
这些指标按回答先算再平均，避免长答案在总体中获得更大权重；同时报告可评覆盖率。
这是本项目拟议的诊断设计，不应将其命名为未经复现的论文原版分数。

水平适配继续沿用独立盲评路线。初学者看术语解释和可理解性，中级看概念联系，
高级看适用条件与推理表达；不以字数、公式数量或术语密度直接替代适配分。
正确性低的答案仍可单独记录适配分，但不能用适配分掩盖事实错误。

## 9. 拟议代码接入方式

新增离线模块，建议位置为 `cs30.evaluation.open_answer_scoring`，与生成器解耦：

```text
保存的 V2 模型输出 + Gold + 评分要点
  -> 输入/版本检查
  -> 规则与语义评审
  -> 逐题结构化评分记录
  -> 人工复核与仲裁记录
  -> M8 报告汇总
```

拟新增输出：

- `open_answer_scores.jsonl`：逐题分数、要点判定、状态和评分来源。
- `open_answer_review_queue.jsonl`：待复核和争议记录，不含自动伪造的人工评分。
- `open_answer_summary.json` / `.csv`：分条件、等级、题型、教材及分母统计。
- `open_answer_report.md`：结果、覆盖率、校准质量与限制。
- 运行 manifest：输入文件、量表、judge 提示词和模型版本的哈希与来源。

逐题至少保存 `run_id`、`question_id`、`answer_sha256`、`rubric_version`、
`rubric_sha256`、`scoring_source`、`score_status`、可空的 `score`、
`criterion_results`、`critical_error`、`judge_model`、`judge_prompt_version`、
原始 judge 输出、规则判定记录和人工复核引用。

建议验收用例：同义正确表达、正确关键词加错误结论、简短术语答案、缺失推导步骤、
数值正负号与单位、合法引用但不支持结论、答案正确但检索证据不足、模型拒答、
技术失败、judge 失败、未决记录分母、Gold 泄漏隔离及学生等级盲化。

离线正确性模块、命令行、人工复核和校准统计已实现，使用说明见
`docs/open-answer-scoring.md`。语义证据支持、水平适配和实验条件差值的正式统计
仍是独立评估项；当前报告不会自动批准正式结论。

## 10. 依据与待确认项

采用事实要点与证据支持分开的思路，参考：

- [FActScore](https://aclanthology.org/2023.emnlp-main.741/)：以原子事实及可靠来源支持度评价事实精确性。
- [RAGChecker](https://arxiv.org/html/2408.08067v2)：提供面向检索与生成模块的细粒度诊断。
- [Judging LLM-as-a-Judge](https://arxiv.org/abs/2306.05685)：分析评审模型的位置、冗长度和自我偏好等偏差。

上述研究提供设计依据，不代表本量表在本项目的物理题上已获得验证。
0/1/2 分制、抽样数量、指标名与工作分工均为本项目建议。

团队需确认：采用 0/1/2 分制和严格得 2 分的主指标；题目要点的复核责任；
judge 的独立性、版本和预算；人工校准样本及可靠性验收标准。
确认后冻结量表与 manifest，再评分正式 Test 输出。任何已有 Test 暴露情况继续如实披露，
新评分方案不会把已暴露的数据重新变成未见测试集。
