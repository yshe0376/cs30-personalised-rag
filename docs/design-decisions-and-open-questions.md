## Pending Decisions (ordered by when they must be resolved)

The closed-loop adaptive KG-RAG architecture document dated 2026-08-30 governs the architecture; see item 7 below. The system architecture and literature mapping document (v1.3) remains the only written detailed design until revised to v1.4; where they agree, use the v1.3 wording. This section records unresolved questions that block other work.

### 1. Formal corpus freeze — deadline 9/11

The OpenStax College Physics 2e parser has merged (#96), SciQ questions are in main, and W4 retrieval and generation use this corpus. The supervisor-promised dataset has not arrived.

**Deadline: 2026-09-11 (Friday of W5).** If it has not arrived, formally freeze OpenStax + SciQ and move this item to Decided. The rationale is in the table above: 13 weeks cannot accommodate a second parser freeze.

Freezing requires B6 (byte-identical output for identical input/configuration), which currently has no parser test coverage. **Do not build indexes before B6 passes**: baseline §6 requires 2 embedding models × 2 chunking settings = 4 indexes, all of which must be rebuilt after every parser change.

### 2. Freezing the A3 Evidence Role taxonomy — the personalisation bottleneck

The six roles (definition / example / comparison / application / derivation / boundary) are designed in baseline §3.3 but **not frozen**. First trial-label 100–200 chunks, check severe class imbalance and especially comparison/application confusion, double-label 20% and report Cohen κ / Krippendorff α, then revise definitions and relabel if agreement is insufficient.

**A scheduling conflict must be resolved.** Baseline §6 says A3 is the personalisation bottleneck and trial labelling → freeze → bulk labelling must finish before Phase 3. The board instead puts `#16` (A3 trial labelling, M5) and `#17` (C4 Level-Aware Reranking, M7) in the same week (W5, 9/07–9/13), with both Dependency fields empty. C4 requires `role_match(level)`, which cannot be computed without a frozen taxonomy.

Do not add `evidence_role` to `EvidenceItem` before A3 is frozen (see the 2026-09-05 ADR-0001 amendment).

### 3. Evaluation set: from 10–15 items to 60 Dev + 180 Test

The baseline §7.1 experiment matrix is frozen: 180 main-experiment questions × 12 conditions, plus a separate model-comparison sample of 60 questions × 6 conditions. `#81` requires 10–15 traceable Gold items first, and an assessment of the path to 60 Dev + 180 Test; Go/No-Go has not been recorded.

Open questions are the construction method (human authoring or LLM generation followed by human filtering—the latter is faster, but writing directly from one passage can make retrieval too easy) and the exact chapter/concept isolation split to prevent leakage, one of `#81`'s acceptance requirements.

Note: the "30~50 question-answer pairs" in `CLAUDE.md` is an old figure; baseline §7.1 takes precedence.

### 4. C4 lambda sweep and the source of confidence

The scoring formula is frozen (baseline §3.4):

```text
λ_eff = λ × confidence
final = (1 − λ_eff) · norm(retrieval_score) + λ_eff · role_match(level)
```

Still open: the λ grid (enough points for a dose-response curve, not binary ON/OFF); the source of `confidence` (architecture-document §1 rules out transcripts, leaving learner self-selection at cold start, followed by Concept Check updates under §14 item 3); and the `norm()` method (BM25 is unbounded, while Dense is in 0–1, motivating the single-knob formula).

These three values have no agreed place in `EvidenceBundle`; `run_provenance` is the likely container, but no convention exists. Decide before `#17` starts.

### 5. Prerequisites for the model comparison

The official brief names Llama / Qwen / Gemma / GPT. Baseline §7.1 freezes the comparison at "3 additional models × 60 questions × 6 conditions = 1080 calls"; reuse the main model outputs without rerunning them.

The generator models and judge are decided; see the 2026-10-23 Decided row. Still open: budget, Llama versus Gemma, and comparison size. Third-party API data use is allowed under the 2026-10-23 Decided row. M6 W6 fixes nine version-pinned embedding comparison candidates (PR #200); the system retriever is in the 2026-10-23 Decided row.

### 6. Human scoring rubric (T4)

The baseline §7.2 workload (3240 automatic assessments, a stratified blind human sample of 360, including 72 double-annotated cases) no longer applies to v2. Since 2026-10-16, all v2 generation-side scoring uses an LLM judge; humans check profiles/rubrics and audit about 20 cases. See Decided.

The three global level profiles and per-level checklists remain unresolved; both must be frozen before judge calibration and developed independently of generation prompts. Earlier considerations still apply: D2 takes six dimensions from LPITutor; D3 must map EduAdapt's grade-aware rubric to this project's three proficiency levels (baseline §8 requires mapping rather than directly comparing raw benchmark scores).
