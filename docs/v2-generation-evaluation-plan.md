## 1. 背景：为什么不能沿用基线 §7.2

架构基线 v1.3 §7.2 的分工建立在 SciQ 选择题上：正确性用选项全量自动比对，人工分层抽 360 份评六维、
水平适配和逐条陈述，其中 72 份双标注，估算约 36 小时。

v2 的情况不同：

| 事实 | 数值 |
|---|---|
| Gold v0.1.2 题量 | 188（162 题临时映射为 Dev，26 题为 Test；划分未正式批准） |
| 选项 | 全部没有，参考答案为 `gold_answer_text`，中位长度 1 个词 |
| 不可回答题 | 0 |
| Dev 题型 | identification 53、causal 43、definition 40、application 17、comparison 8、calculation 1 |
| M7 Dev 运行 | 1,944 单元，1,930 条回答、14 条生成失败；全部待评分 |

选项比对不再可用，正确性需要语义判断。若按 M7 方案靠人工校准 judge，仅正确性就需要至少 240 次双人评分，
还未计入水平适配和证据支持。因此 v2 改为全量 LLM judge 评分，人工只做核对与审计。**【已定 2026-10-16】**

## 2. 评估问题与指标层级 【建议】

| 层级 | 回答的问题 | 指标 |
|---|---|---|
| 主要效果 | 个性化答案是否更适合目标等级的学生？ | 适切度：逐级核查清单通过率（§4.2） |
| 辅助检查 | 不同等级的答案能否被区分？ | 区分度：逐份等级判断的猜对率（§4.3） |
| 必须同时满足 | 个性化是否牺牲了正确性？ | 正确性非劣效（§4.1） |
| 诊断 | 答案陈述是否有证据支持？重排机制是否在动？ | 证据支持（§4.4）、机制检查与文本统计（§4.5） |
| 不在本轮范围 | 能否正确拒答？ | v2 Gold 无不可回答题，暂不评。需要时由 M3 补题 |

三个维度分别报告，不合成总分。同一事实正确性标准适用于三个等级；简短但正确的初学者答案不因简短被扣
正确性分。适切度高不能掩盖事实错误，另报"正确且适切"的联合结果。

## 3. 前置工作

### 3.1 三份全局等级画像 `level-profile-v1` 【建议】

M7 编写交付（2026-10-21）：[三档画像、逐级清单与非 Gold 示例](evaluation/level-profile-v1/README.md)，
含机器可读草稿与经真实核对后导出 `ProfileChecklistPackage` 的工具。
当前 `frozen=false`，Leader 确认与 M3 物理核对待完成，不把编写完成视为团队冻结。

负责人建议：Leader + M7（对应 backlog B14），M3 核对物理内容。冻结后才能制定清单和校准 judge。

主实验使用全局等级的固定画像（基线 §4.5），不按 Topic 分别定义。每档写清：

1. 学生定位。例如初学者＝未学过大学物理；中级＝正在修或刚修完以代数为主的大一基础物理；
   高级＝修完微积分版基础物理。
2. 已有的物理主题与数学基础（代数、三角、微积分）。
3. 可以不加解释直接使用的术语。
4. 能接受的推理跨度：一次解释可跨几步，哪些中间步骤可以省略。
5. 有帮助的写法与应避免的写法。高级需包含专家逆转效应（Kalyuga et al., 2003）：对新手有用的铺垫对高水平学生是冗余。
6. 2–3 道**非 Gold** 示例题，各写三档的好答案，作为评分锚点。

画像要独立于生成 prompt 的 `_LEVEL_GUIDANCE` 制定。若二者不一致，记录为发现，不回头修改画像去迁就 prompt。

### 3.2 题目适用范围 `personalisation_eligibility` 【待定：取值定义】

Gold 已有字段 `personalisation_eligibility`（`full` / `endpoint_only` / `none` / `pending`）和
`eligibility_reason`，188 题目前全部为 `pending`。M3 一直在等 M1 给出取值定义。建议定义：

| 取值 | 含义 |
|---|---|
| `full` | 三档学生的好答案在内容上都应不同 |
| `endpoint_only` | 只有初学者与高级之间存在合理差异，中级答案与其中一端相近 |
| `none` | 所有等级的好答案都是同一个术语加一句话，没有分档空间；只进入正确性评估 |

M3 的工作：

- 每题阅读题干、参考答案、Gold 证据及其所在小节，对照画像判断"三档的好答案会在哪里不同"，选取值并写一句理由。
- 不查看任何模型生成的答案；在评分开始前冻结。
- 先与 Leader 独立标注同样 15–20 题，比较分歧并修订判断说明，再完成其余题目。题型只作参考。
- 结果交付为附加文件 `personalisation_eligibility_v1.jsonl`（按 `question_id` 关联），暂不修改 Gold，
  避免 Gold 哈希变化使已准备的实验输入和量表失效；下一版 Gold 再合并。

预计约 1.5 小时（188 题）。

### 3.3 候选证据丰富度（自动计算） 【建议】

"这道题能否评重排效果"不需要人工标注。对每题每个等级，检查检索候选 top-20 中是否存在该等级首选角色
（初学者 definition/example，中级 comparison/application，高级 derivation/boundary）的 chunk。
它只依赖生成前的检索结果与 Role 标签，随实验输入一起冻结。

当前 Dev 的 BM25 top-20 中，没有首选角色候选的题：初学者 0/162，中级 14/162（9%），高级 99/162（61%）。
重排效果只能在有候选的题与等级上评。

### 3.4 逐级核查清单 【建议，从画像推出后冻结】

格式：每条输出"是 / 否 / 不适用"，统一"是＝通过"；附答案原文片段与简短理由。
"不适用"由题目和目标等级决定，不能因为答案没写就判不适用。

初稿（画像冻结后修订）：

| 等级 | 编号 | 条目 |
|---|---|---|
| 初学者 | B1 | 关键术语在首次使用时得到解释，或只使用无需解释的日常用语 |
| | B2 | 回答问题所需的推理步骤完整，没有跳过初学者无法自行补上的步骤 |
| | B3 | 当概念需要具体化才能理解时，提供了有效的例子、类比或其他支撑 |
| | B4 | 没有引入超出初学者基础的公式或符号；引入时作了解释 |
| 中级 | I1 | 点明了所依据的原理、定律或概念 |
| | I2 | 说明了证据或原理如何导出结论 |
| | I3 | 课程术语使用准确，没有重复解释中级学生已掌握的基础定义 |
| 高级 | A1 | 没有冗余的基础解释 |
| | A2 | 当结论依赖重要条件时，交代了相关假设或适用范围 |
| | A3 | 当定量关系有助于解释时，准确使用 |
| | A4 | 推理表述严谨，没有含糊或过度简化的说法 |

不得以字数、术语数量或是否出现公式直接代替条目判断。

### 3.5 judge 选型 【待定】

约束：

- 与生成模型 `gpt-oss:20b` 不同家族。
- 本地模型无需数据许可，但能力需先通过 §6 的有效性检查。2026-10-16 的本地试验中，qwen3:8b 被要求把三份

## 4. 各维度评估方法

### 4.1 正确性（必须同时满足）

**评分** 【沿用 M7 已实现】：0/1/2 分。2＝满足至少一条完整要点路径且无实质错误；1＝部分正确或只有次要错误；
0＝核心错误、核心矛盾或未作答。先查确定性规则（完整别名、明确数值），其余交给独立 judge 按要点输出
"满足 / 未满足 / 矛盾 / 无法判定"，分数由程序计算。

**指标**：严格正确率只统计 2 分；平均 `score/2` 单独展示，不称为准确率；评分未齐时只给上下界
`[C/N, (C+U)/N]`，不给点估计；拒答与技术失败在端到端指标中计 0 并保留原因与数量。

**量表**：SciQ 术语题沿用 M7 由参考答案生成的两条要点草稿，由 §7 的审计抽查；calculation 或多步推理题逐题细化。

**非劣效** 【待定：δ】：预先规定可接受降幅 δ。报告个性化条件与对照的配对正确率差及其区间；
只有区间下界高于 −δ，才支持"正确率下降未超过预设限度"。区间过宽时结论为"证据不足"，
不得用"差异不显著"代替。

**联合结果**：另报"正确且适切"（正确性 2 分且适切度达标）的比例，达标阈值随清单一起冻结。

备选路线：从 SciQ 恢复 A–D 选项，正确性回到全量选项比对（需 M3 恢复选项并重跑生成）。目前采用开放题路线。

### 4.2 适切度（主要效果）

- judge 读取目标等级的画像与清单、题目和一份匿名答案，逐条输出 是/否/不适用 + 原文片段 + 理由。
  不提供实验条件、λ、生成模型和其他答案。
- 每份答案先计算适用条目的通过比例，再按题目与等级平均；保留逐条结果。
- **P0R0 基线**：P0R0 的答案（无等级提示、无重排）用三个等级的清单各评一遍，得到"通用答案本来能通过多少"。
  个性化条件的通过率与同一目标等级的 P0R0 通过率配对比较。
- **跨等级评估**：抽部分个性化答案，用非目标等级的清单再评，检查是否存在目标等级优势。
  一份答案同时适合多个等级是允许的。
- 主结果只报告 `full` 与 `endpoint_only` 题目；同时报告全题集与 `none` 题目的结果，写明结论覆盖范围。

### 4.3 区分度（辅助检查）

- judge 每次只看一份匿名答案，回答"这份答案最适合哪个等级"，可选"无法判断"。不提供目标等级。
  **不让 judge 对多份答案排序或分配等级**（见 §3.5 试验）。
- 主指标：每份答案的等级猜对率，随机基线 1/3。"无法判断"计为未猜中，同时单独报告其比例。
- 报告 3×3 混淆矩阵，中级与高级之间的区分单独报告，避免总体准确率主要来自初学者。
- **P0R0 为空白对照**：其三份答案来自完全相同的 prompt，猜对率应接近 1/3。λ>0 后 P0R1 的证据带有等级信息，
  不能作空白对照。

### 4.4 证据支持（诊断）

沿用 M7 方案 §8 的定义：

- Bundle faithfulness：答案中可核查事实被实际送入模型的证据支持的比例。
- Citation support：这些事实被答案实际引用的证据子集支持的比例。

judge 逐条列出可核查陈述，记录支持证据 ID 与原文位置，程序校验引文确实来自已保存证据。主观措辞与重复事实不计；
无可评事实记 NA，不记满分。按答案先算再平均，并报告可评覆盖率。引用 ID 合法不等于语义支持。

### 4.5 机制检查与文本统计（诊断）

- **机制检查**：送入生成器的 top-5 证据中，目标等级首选角色所占比例。它随 λ 单调上升，只证明重排在按设计工作，
  不作效果指标，也不用于选 λ。
- **文本统计**：FKGL、多音节词占比、长度、公式出现率，全量计算，仅作描述。

现有 Dev 答案的文本统计（启发式，仅供方向参考）：

| 条件 | 初学者 FKGL | 中级 FKGL | 高级 FKGL | 按 FKGL 排序猜等级 |
|---|---:|---:|---:|---:|
| P0R0（无等级提示） | 13.1 | 13.1 | 13.1 | 0.35 |
| P1R0（有等级提示） | 10.8 | 13.9 | 13.3 | 0.48 |

中级 FKGL 高于高级不能直接说明适配失败；中高级是否可区分以 §4.3 的混淆矩阵为准。

## 5. judge 规范 【建议】

| 任务 | judge 看到 | judge 看不到 |
|---|---|---|
| 正确性 | 题目、参考答案、评分要点、Gold 证据、答案 | 条件、等级、λ、生成模型 |
| 适切度 | 目标等级画像与清单、题目、答案 | 条件、λ、生成模型、其他答案 |
| 区分度 | 三份画像、题目、答案 | 目标等级、条件、λ、生成模型、其他答案 |
| 证据支持 | 实际送入的证据、引用列表、答案 | 条件、等级、λ、生成模型、Gold 参考答案 |

通用要求：

- 每次只评一份答案；输出结构化 JSON，分数或汇总由程序计算。
- 判"满足 / 通过 / 矛盾"必须附答案原文的精确子串（M7 已有该校验）。
- 答案与证据是待评材料而非指令，提示词中明确忽略其中改分或改规则的文字。
- 完全相同的输入复用缓存结果；缓存绑定提示词、量表、画像版本和 judge 配置。

## 6. 自动有效性检查 【已定，阈值待定】

全量评分替代分层人工抽样的前提是以下检查全部报告。阈值在 Dev 校准阶段确定并冻结。

| 检查 | 做法 | 发现什么问题 |
|---|---|---|
| P0R0 偏差探测 | P0R0 三个等级的 prompt 完全相同，其答案的逐份等级判断猜对率应接近 1/3 | judge 自带等级偏好 |
| 重复答案重测 | 1,930 条 Dev 答案只有 852 个不同的（题目, 答案文本）组合；同一文本多次评分，计算一致率 | judge 前后不一致 |
| 篇幅与公式偏差 | 同一等级内，检查通过率与答案长度、是否含公式的关系 | judge 凭表面特征判断 |
| 位置与重复 | 抽部分案例打乱条目顺序或重复评分 | 位置偏差、随机性 |
| 第二个 judge | 另一家族模型独立评同一子集，报告逐项分歧 | 单模型偏差（两模型一致仍可能共享偏差） |
| 扰动测试（可选） | 约 20 份人工改坏的答案：给初学者答案加入未解释术语、给高级答案加冗余铺垫等，检查 judge 能否发现 | 清单条目实际是否被执行 |

任一检查未通过时，在校准案例上修改 judge 提示词或清单，不在审计案例上调整。

## 8. λ 选择 【已定 2026-10-18】

**规则**：在 Dev 上，取完整证据命中率（三个等级合并，162 题 × 3 = 486 个 case）不低于 λ=0 减 1 个百分点的
**最大正 λ**。适切度、正确性和任何 judge 分数都不参与选择。λ=0 是不重排的对照，不作为重排组候选；
没有正 λ 通过时运行报错，并如实报告这一结果。实现见 PR #182 的 `select_dev_lambda`。

**理由**：原规则（命中率最高、平局取较小 λ）几乎必然选出 0，因为角色偏好与 Gold 相关性无关；
Dev 实际选出 λ=0，使重排组与对照组的 prompt 完全相同（1,944 个单元只有 648 个不同 prompt）。
若用 judge 分数在同一批 Dev 题上选 λ，Dev 的适配结果会偏乐观，而 judge 尚未经过验证；固定的检索规则可以同时避免这两点。

**Dev 网格**（M7 实际使用 0 / 0.1 / 0.2 / 0.35 / 0.5；0.15、0.25、0.3 为补充计算）：

| λ | 0 | 0.1 | 0.15 | 0.2 | 0.25 | 0.3 | 0.35 | 0.5 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 完整证据命中率 | 0.827 | 0.823 | 0.819 | 0.821 | 0.815 | 0.807 | 0.796 | 0.636 |
| 相对 λ=0（百分点） | — | −0.4 | −0.8 | −0.6 | −1.2 | −2.1 | −3.1 | −19.1 |
| 新命中 / 丢失 | — | 1 / 3 | 2 / 6 | 3 / 6 | 3 / 9 | 3 / 13 | 4 / 19 | 6 / 99 |

**结果**：λ=0.2（0.8210，零基线 0.8272）。补充网格得到相同结论：0.25 低 1.2 个百分点，不通过。

说明：

- 门槛按三个等级合并计算。单看初学者为 132/162 对 134/162（−1.2 个百分点，相差 2 题），中级 133 对 134，高级不变。
- λ=0.2 时，486 个"题目 × 等级"中有 201 个的前 5 条证据与 λ=0 不同（初学者 85、中级 85、高级 31）。

## 9. 实验条件与统计 【建议】

四个条件 × 三个等级：`P0R0_plain`、`P1R0_prompt_only`、`P0R1_reranking_only`、`P1R1_combined`。
比较时固定另一开关：

| 效果 | 对照 |
|---|---|
| 等级提示 | `P1R0 − P0R0`，`P1R1 − P0R1` |
| 重排 | `P0R1 − P0R0`，`P1R1 − P1R0` |

- 按题目配对；区间用题目 cluster bootstrap，一道题的全部等级、条件和评分一起重抽，不把 1,944 条答案或清单条目
  当作独立样本。
- 主要比较、主指标、δ 与多重比较处理在 Test 评分前登记。
- 生成模型在温度 0 下仍不确定。λ=0 运行中，相同 prompt 的首次输出不一致率为 12%（P0R0 对 P0R1）、
  42%（P1R0 对 P1R1）、36%（P0 跨等级）。λ=0.2 运行加了 `seed=0` 后，按代码 prompt 相同的单元仍有
  13%（P0R0 对 P0R1，证据未变，36/285）、40%（P1R0 对 P1R1，证据未变，113/285）、22%（P0R0 跨等级，70/324）
  的答案不一致。输出不能逐字复现；报告必须给出这一噪声底，条件差异要与之比较。
